# Scrappy Forge roadmap

This is a direction, not a promise of dates.

## Now — make the public beta boringly reliable

- stable CI on supported Python versions
- contributor setup that works from a clean machine
- live-provider compatibility checks beyond scripted fixtures
- clearer install/update/uninstall path
- tighter permission and failure messages
- more regression coverage for apply/rollback and interrupted actions
- reproducible release verification
- public contribution workflow and issue hygiene

## Next — better engineering substrate

- stronger model/provider routing based on capability and task requirements
- richer evaluation of completed coding tasks
- better long-running mission/task state
- improved recovery after partial tool failure
- safer extension discovery and trust UX
- more useful project/world-state queries without turning them into hidden authority

## Later — only after evidence

- independently reviewed security posture
- signed releases / stronger supply-chain verification
- broader supported platforms
- carefully bounded multi-agent collaboration where it beats one-agent execution
- deeper integration with persistent continuity systems such as Vault Zeta

## Things I do not want to fake

I do not want roadmap items to become claims before they are measured.

That means no “AGI”, “10× developer”, “fully autonomous”, “production safe”, or “universal plugin support” label unless there is evidence strong enough to defend it.
